## Eligibility Regression and Scaling Readiness

The automated suite has 71 tests. Eight realistic synthetic applicant scenarios are run against each of the five real unreviewed records (40 program/profile checks): apparently complete CS graduate, unfinished degree/partial transcript, low subject credits with no equivalence approval, missing certificates, wrong test/weak language evidence, old certificate, unmatched semester and fabricated document excerpt. Every result remains `not_enough_data` without a confirmed blocker. This is the expected trust boundary, not a claim these applicants meet the official policies.

The existing 31 V2 tests and reviewed **fictional policy** fixtures separately exercise decisive mandatory failures, complete versus partial subject-credit shortfalls, exact language variants/scores, conditional routes and source/semester uncertainty. No real source was given a fake human approval to produce a positive or negative verdict. No eligibility-engine rule changes were needed; actual fixes concern ingestion fidelity, review omissions, stale templates and frontend loading.

The pipeline can support a controlled expansion of draft capture, but **the catalog is not ready to publish 50 verified programs or make a PostgreSQL service the next priority**. There are zero human-approved complete pilot inventories. First complete one end-to-end human review with a controlling regulation, named intake, applicant scopes and supported exception rules; then repeat for all five with program-specific positive/negative reviewed fixtures. Add source roles/languages/amendment dates, source-conflict dispositions, recheck scheduling/backoff and transactional publication before centralizing trust. Keep stable program/version/source IDs and DTOs for a future PostgreSQL migration; storage choice does not resolve the current evidence and modeling gaps.
